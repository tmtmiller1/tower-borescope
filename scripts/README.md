# scripts

Scripts that prepare the development environment, build the application bundle, collect the license texts of its components, check the code against the size and complexity limits and score mutation runs.

## Files

- `setup.sh`: installs Homebrew libusb, ffmpeg and uv when missing, syncs the uv environment with every dependency group and the `virtual-camera` extra (pyvirtualcam, which the downloadable application leaves out), and writes `.env` with the Homebrew library locations.
- `build_app.sh`: runs `build_opencv.sh`, then creates the build environment `build/venv` with `uv sync --locked` (the build and dev groups, no extras, so no pyvirtualcam), replaces the PyPI opencv-python wheel there with the OpenCV build and checks that `cv2.getBuildInformation()` in that environment matches the build; the project `.venv` is not touched, and PyInstaller, `collect_licenses.py` and every check run from `build/venv`. It downloads the pinned libusb and ffmpeg release tarballs into `build/`, verifies their SHA-256 sums and compiles both for the minimum macOS version with at most four make jobs. The ffmpeg build is LGPL-2.1-or-later: `--disable-everything` and `--disable-autodetect` plus the AVFoundation input device, the MJPEG, rawvideo, image2, MOV, Matroska and AVI demuxers, the MJPEG, PNG, rawvideo, H.264 and PCM decoders, the VideoToolbox H.264, AudioToolbox AAC and rawvideo encoders, the MOV, MP4, Matroska, AVI and rawvideo muxers, the MJPEG, PNG and H.264 parsers, the scale, format and resample filters and the file, pipe and fd protocols (ffmpeg 9 reads the `-` input through fd), linked against macOS system libraries only; its configure line is kept in `build/ffmpeg-<version>-<arch>/configure.txt`, and the build is checked for every feature, for a stream copy of MJPEG piped into standard input, for reading the first frame of that file through `tower_borescope.capture.ffmpeg.first_frame`, for the LGPL, for system-only linkage and for the minimum macOS version. The script then draws the icon, packs `Tower Borescope.app` through PyInstaller without pyvirtualcam, mypy, setuptools, yaml, click, rich, pytest and the other modules reached only through optional imports, removes Qt Virtual Keyboard, Qt Quick, QML and OpenGL with the `platforminputcontexts` plugin that loads them, fails when any of them or any FFmpeg library remain or when the bundled `cv2` extension links a library outside macOS, and collects the license texts into `Contents/Resources/licenses`: this project's `LICENSE` and `THIRD_PARTY_NOTICES.md`, the full LGPL-3.0 and GPL-3.0 texts, ffmpeg's `COPYING.LGPLv2.1`, `LICENSE.md` and configure line, libusb's `COPYING`, the Qt for Python texts, the OpenCV build's license files, CMake options and build information in `opencv/` and, through `collect_licenses.py`, the files of every bundled Python distribution and CPython. Last it signs the bundle, checks that it renders a window with `--test-shot` within 120 seconds (a hung application is stopped with its child processes and fails the build), writes the disk image with `LICENSE` and `THIRD_PARTY_NOTICES.md` beside the application and installs the application into `~/Applications`.
- `build_opencv.sh`: builds the OpenCV wheel for the application bundle, because every opencv-python wheel on PyPI for macOS links GPL-configured FFmpeg libraries. It downloads the opencv-python 5.0.0.93 sdist and, on arm64, the KleidiCV 26.03 tarball, verifies their SHA-256 sums, installs pinned build tools (CMake, scikit-build, setuptools, NumPy 2.0.2) into `build/opencv-tools` and compiles, with at most four make jobs, for macOS 13.0: the core, flann, geometry, imgproc, imgcodecs and video modules and the Python bindings; no FFmpeg, GStreamer, AVFoundation video I/O or plugins; the zlib, libjpeg-turbo, libpng, libtiff, libwebp and OpenJPEG codecs from OpenCV's bundled sources, with Homebrew prefixes ignored; no Intel IPP, font download, OpenEXR or AVIF. The only source change is to the typing stub generator in `api_refinement.py` and `generation.py`: it skips refinements and aliases that name functions or classes of modules that are not built, so the wheel keeps `py.typed` and the stubs of the built modules; each replaced text must occur exactly once or the build stops. The result goes to `build/opencv-<version>-<arch>-<options hash>/`: the wheel, `cmake-args.txt`, `build-information.txt`, `build.log`, `build-seconds.txt` and `licenses/` (the OpenCV license and the license files of every compiled-in library, whose texts also replace the wheel's `LICENSE-3RD-PARTY.txt`). The build fails when CMake downloads a file itself, when `cv2` links a library outside macOS or misses the architecture or minimum macOS version, or when `cv2.getBuildInformation()` reports other modules, a video backend or other third-party libraries. A later run with the same options prints the cached wheel; `--key` prints the folder name, which the release workflow uses as its cache key. An Intel build needs `nasm` for libjpeg-turbo.
- `collect_licenses.py`: `python scripts/collect_licenses.py WORKPATH APP DEST [--include NAME] [--covered NAME]` maps the files recorded in PyInstaller's `PYZ-00.toc`, `PKG-00.toc` and `COLLECT-00.toc` that are still inside the bundle to the installed distributions whose `RECORD` lists them, copies each distribution's `.dist-info` license files to `DEST/python/<name>-<version>/`, copies the CPython license and writes `DEST/python/DISTRIBUTIONS.txt`. `--include` adds a distribution without a recorded source file (the PyInstaller bootloader); the exit status is 1 when a bundled distribution has no license file and `--covered` does not name it.
- `app_entry.py`: PyInstaller entry point that enables multiprocessing in the frozen application and starts it.
- `check_limits.py`: standard-library checker for the limits in `AGENTS.md`. `python scripts/check_limits.py [PATH ...]` reads the `.py` files under the given paths (`src`, `tests` and `scripts` by default) and reports, one line each as `path:line: RULE message (value, limit)`, every line over 90 characters (`LINE`), module over 400 lines (`MODULE`), function over 50 lines (`FUNC`), class over 200 lines (`CLASS`), class with more than 20 methods (`METHODS`), 15 public methods (`PUBLIC`) or a weighted method complexity above 30 (`WMC`), function with more than 5 parameters (`PARAMS`), nesting deeper than 4 (`NESTING`) or cyclomatic complexity above 10 (`CC`), missing docstring on a module or on a public class, function or method outside test modules (`DOC`), and module that does not parse (`PARSE`). The metrics match the Tower audit: a definition spans from its `def` or `class` line to its last line, decorators excluded and docstring included; `self` and `cls` do not count as parameters; nested definitions are measured on their own; closures and an `__init__` in a documented class need no docstring. The exit status is 1 when anything is reported, and CI runs the script after radon.
- `mutation_score.py`: mutation scores for each area of the package from a finished `mutmut run`. It reads the per-file records in `mutants/`, prints the killed, survived, unreached, timed out, suspicious and crashed mutants and the score of each subpackage, and with `--gate` exits 1 when a score falls more than one point below its floor in `docs/mutation_baseline.json` or when mutants remain unchecked. `--update-baseline` records the scores of a complete run as the new floors.
